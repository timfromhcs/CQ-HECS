# CQ-HECS v2.5.0 Findings & Defect Ledger

## Defect Ledger

| Finding ID | Severity | Description | Root Cause | Fix Strategy | Status |
|---|---|---|---|---|---|
| **CQ-V25-01** | P1 | Absence of execution mode typing allows ambiguous simulation vs hardware semantics | Prior `SimulationResult` lacked explicit `execution_mode` enum, risking confusion between ideal simulation and noisy/hardware emulation | Added `ExecutionMode` enum (`IDEAL_CLASSICAL`, `NOISY_CLASSICAL`, `REAL_HARDWARE`) to `cqhecs.result` and require it on all results; added `backend_profile_id`, `noise_model_id`, `is_real_hardware` fields. | RESOLVED (`tests/test_hardware_bridge.py`) |
| **CQ-V25-02** | P1 | Lack of structured backend calibration profile schema | `CQHecsProvider` only exposed hardcoded qubit counts with no topology, basis gate or error rate representation | Implemented `BackendProfile` dataclass with schema versioning (`1.0`), strict validation (rejecting negative rates, self-loops, out-of-range edges), and Qiskit `Target` generation. | RESOLVED (`cqhecs/hardware_bridge.py`, `tests/test_hardware_bridge.py`) |
| **CQ-V25-03** | P0 | Potential silent fallback risk if hardware provider unavailable | Standard quantum frameworks frequently fall back to local simulators when a remote device fails or is unauthorized | Enforced strict fail-closed boundary with `HardwareAuthorizationRequiredError` and `HardwareAuthenticationError`; under no circumstances does `RealHardwareBackend` fall back to simulation. Guarded by Mutant 15. | RESOLVED (`cqhecs/hardware_bridge.py`, `tests/test_hardware_bridge.py`, Mutant 15) |
| **CQ-V25-04** | P1 | No mathematically validated noise channel engine in classical emulator | CQ-HECS had zero noise-modelling capabilities, preventing noisy verification | Implemented narrow Kraus-based channels (`DepolarizingChannel`, `AmplitudeDampingChannel`, `PhaseDampingChannel`, `TwoQubitDepolarizingChannel`, `ReadoutErrorChannel`) with verified trace preservation, Hermiticity, and completeness checks ($\sum K_k^\dagger K_k = I_d$); created `NoisyDensityMatrixBackend` for exact float64 emulation <= 10 qubits with Hoeffding total variation bounds. | RESOLVED (`cqhecs/hardware_bridge.py`, `cqhecs/backends/noisy_density_matrix.py`, `tests/test_noisy_density_matrix.py`) |
| **CQ-V25-05** | P2 | CLI lacked command to inspect backend profiles and run noisy emulation | CLI only had `run`, `expect`, `analyze`, `backend list` | Added `cq-hecs profile list`, `cq-hecs profile show <NAME>`, and `--profile <NAME>` / `--noisy` options to `cq-hecs run`. | RESOLVED (`cqhecs/cli.py`, `tests/test_cli_contract.py`) |
