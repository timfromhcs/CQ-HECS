## 4. Entscheidungen / Stopp-Punkte für dich
1. **Versionsnummer:** v6-rc beschloss `6.0.0` (D-007), du sagst „v7 stable". Der Nummernsprung 5→7 ist unüblich. Empfehlung: Release als `7.0.0`, D-007 überschreiben und in Migration vermerken – bitte bestätigen.
2. **Release-Freigabe:** Dein Auftrag („dann main mergen + release") gilt als Freigabe, aber ich stoppe vor dem Merge und zeige das Audit (RELEASE_CANDIDATE_AUDIT) – Merge löst Production-Deploy aus.
3. **Nicht ausführbar ohne dich:** bezahlte QPU-Läufe (SYK-Follow-up F-10/F-11) und Credential-Dinge bleiben aus; echte Windows-Clean-VM-Prüfung braucht eine VM (sonst `NOT RUN`, und das blockiert W14 laut Gate).
4. Ressourcen: 5 Agents × 5 Wellen ist teuer; Lean-Build (~5 min) und Full-Suite (~9 min) laufen je Welle.

## 5. Risiken
- Ungepushter `agent/v6-rc` → Welle 0 zuerst.
- Harte Gates W13/W14 erlauben keine Deferrals: Fehlende Windows-VM oder Vulkan-GPU können den Release auf `RELEASE_CANDIDATE_ONLY` begrenzen.
- Python 3.14 + python-sat Abort (0xC0000409): isoliert testen, nicht unterdrücken.
